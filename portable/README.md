# portable/

This directory is the version-controlled source for STF agents and shared contracts. A source directory is not yet a validated release; no home directory or host application is authoritative.

---

```

├── schemas/                         # JSON Schema 2020-12 contracts (5 schemas)

│
└── {agent-name}/                    # One directory per agent
    ├── docs/                        # Agent-specific documentation

    ├── plan/                        # Active agent plan; archive/ for completed inputs
    └── export/                      # Installable agent artefacts
        ├── agents/                  # Agent role contracts (.md files)
        ├── mcp/                     # MCP server configuration stubs (.yaml)
        ├── scripts/                 # Generation and utility scripts
        │   └── generate-bob-adapter.sh   # Generates .bob/skills/ from export/skills/
        ├── skills/                  # Canonical skill files (.md) — NEVER edit .bob/skills/ directly
        └── templates/               # Communication template stubs and catalog
```

## Convention rules

### 1. One agent = one directory
Each agent lives under `portable/{agent-name}/`. The name must be kebab-case (`^[a-z0-9]+(-[a-z0-9]+)*$`), matching the `agent_id` in `agent.schema.json`.

### 2. `export/skills/` is the canonical skill source
- All skill edits go into `export/skills/*.md`.
- `.bob/skills/` (home directory) is generated by `export/scripts/generate-bob-adapter.sh` and **never edited manually**.
- If `.bob/skills/` and `export/skills/` diverge, `export/skills/` wins.

### 3. Keep agent-specific information with its agent
The Terraform design, dashboard, active plan, and completed planning inputs live under `portable/terraform-support-agent/`. Shared STF architecture stays at the repo root. Design and archived source files are not runtime payloads.

### 4. Separate generic and agent-specific installers
```bash
bash install.sh --agent terraform-support-agent --hosts bob --dry-run
bash portable/terraform-support-agent/installer.sh help
```
Root `install.sh` targets generic host skills. The Terraform `installer.sh` owns that agent's lifecycle. Its expanded menu and release verification are planned in the [agent priority plan](terraform-support-agent/plan/portability-readiness-plan.md); they are not yet proven. Use dry runs until the target-host checks pass.

### 5. Phase boundaries
| Phase | What gets created |
|---|---|
| 1–2 | Repository foundation and Terraform-agent design |
| 3 | Skills, templates, memory seeds, and evaluation cases |
| 3b (active) | Installer, optional A2A scaffold, file consolidation, and validation |
| 4+ | Reviewed connectors, delegation, and controlled automation |

## Adding a new agent

1. Create `portable/{new-agent-name}/docs/design/` and populate design documents.
2. Create `portable/{new-agent-name}/plan/` with an active plan and `archive/` for completed planning inputs.
3. Create `portable/{new-agent-name}/export/` with `agents/`, `skills/`, `mcp/`, `scripts/`, `templates/` subdirectories.
4. Add a canonical skill file in `export/skills/` for each skill.
5. Copy `generate-bob-adapter.sh` from an existing agent and adjust paths.
6. Check generic installer discovery and host compatibility before advertising the new agent.
7. Update this README's "Current agents" table.
