# portable/

This directory is the **portable bundle** — the stable, version-controlled source for all STF agents and skills. It is the canonical source; no home directory or host application is authoritative.

---

## Directory layout

```
portable/
├── bundle.yaml                      # Bundle manifest (draft — see schemas/bundle.schema.json)
├── adapters/README.md               # Future adapter documentation
├── schemas/                         # JSON Schema 2020-12 contracts (5 schemas)
│   ├── README.md
│   ├── agent.schema.json
│   ├── bundle.schema.json
│   ├── result.schema.json
│   ├── task.schema.json
│   └── trace-event.schema.json
│
└── {agent-name}/                    # One directory per agent
    ├── docs/                        # Agent-specific documentation
    │   └── design/                  # Design phase documents (00–07 for terraform-support-agent)
    ├── plan/                        # Original planning documents and references
    └── export/                      # Installable agent artefacts
        ├── agents/                  # Agent role contracts (.md files)
        ├── mcp/                     # MCP server configuration stubs (.yaml)
        ├── scripts/                 # Generation and utility scripts
        │   └── generate-bob-adapter.sh   # Generates .bob/skills/ from export/skills/
        ├── skills/                  # Canonical skill files (.md) — NEVER edit .bob/skills/ directly
        └── templates/               # Communication template stubs and catalog
```

## Convention rules

### 1. One agent = one directory
Each agent lives under `portable/{agent-name}/`. The name must be kebab-case (`^[a-z0-9]+(-[a-z0-9]+)*$`), matching the `agent_id` in `agent.schema.json`.

### 2. `export/skills/` is the canonical skill source
- All skill edits go into `export/skills/*.md`.
- `.bob/skills/` (home directory) is generated by `export/scripts/generate-bob-adapter.sh` and **never edited manually**.
- If `.bob/skills/` and `export/skills/` diverge, `export/skills/` wins.

### 3. `docs/` and `plan/` are read-only during installation
The `docs/design/` and `plan/` files are design-phase documentation. The installer reads only from `export/`.

### 4. Installation is done by `install.sh` (repo root)
```bash
bash install.sh               # interactive
bash install.sh --dry-run     # preview only
bash install.sh --agent terraform-support-agent --hosts bob --dry-run
```
The installer supports: IBM Bob, Codex, Google Gemini, OpenCode, Claude Code.
See `install.sh --help` for all options.

### 5. Phase boundaries
| Phase | What gets created |
|---|---|
| 1 (now) | Directory structure, design docs, skill stubs, script stubs, installer skeleton |
| 3 | Real skill content, Bob adapter generation, template files |
| 4 | MCP server configs activated, optional integration connectors |
| 5 | Eval cases and memory entries |
| 6 | Reproduction environment setup |

## Adding a new agent

1. Create `portable/{new-agent-name}/docs/design/` and populate design documents.
2. Create `portable/{new-agent-name}/plan/` with planning references.
3. Create `portable/{new-agent-name}/export/` with `agents/`, `skills/`, `mcp/`, `scripts/`, `templates/` subdirectories.
4. Add a `SKILL.md` stub for each skill in `export/skills/`.
5. Copy `generate-bob-adapter.sh` from an existing agent and adjust paths.
6. The installer will automatically detect the new agent (it scans for `export/skills/*.md`).
7. Update this README's "Current agents" table.
