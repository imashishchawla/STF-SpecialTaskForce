01 / Getting oriented

Your first five minutes.

  1. Open this release folder in IBM Bob. Project skills belong to this workspace. No changes to your global Bob settings are required.
  2. Install from Bob’s terminal if you have not already. Python 3.9 or later is required. The preview step writes nothing and opens no browser.
    python3 install.py --dry-run
python3 install.py
    This page opens after success. For headless use: python3 install.py --no-open.
  3. Reload the Bob window. Select Terraform Support Preview in the mode picker. In Settings → Skills, verify the five terraform- skills.
  4. Keep tool approvals enabled. The preview mode provides read and skill tools only. It does not grant terminal execution, editing, MCP, or subagent spawning.
  5. Start with a made-up report. Use the example below. No personal name, credentials, or real case number is required.
Use terraform-intake for this synthetic report:
A Terraform run failed after a provider version upgrade.
Expected: the same configuration plans successfully.
Observed: a schema validation error, with no infrastructure changed.
Ask only for missing evidence needed to distinguish likely causes.
Do not run commands or contact a backend.

Preferences are optional. Leave signature fields blank to keep placeholders. Changing your local preferences does not update the public project.

02 / The operating loop

Investigate one step at a time.

ClarifyClassifyCollectIsolateIdentifyRemediateValidateDocument

Describe the expected and actual behavior. Identify the product and exact versions. Supply only the sanitized evidence that changes the next diagnostic step. Ask for ranked hypotheses and one discriminating check for each.

Evidence before conclusions

A customer report is a report. An observation needs supplied evidence. A hypothesis needs a check. A confirmed cause needs evidence that distinguishes it from alternatives.

Review before communication

Review conflicting evidence, version applicability, scope, and rollback before drafting a response. All replies, handoffs, and closure notes remain drafts for human review.

Role instructions are performed sequentially in this conversation. They do not launch a separate fleet. If a source cannot be retrieved, the agent should state that limit and offer a manual public documentation check.

04 / Before anything enters the chat

Protect the input first.

Remove personal names, email addresses, customer or company identifiers, account/subscription IDs, workspace/run IDs, credentials, private URLs, and sensitive log content before sending input to Bob. Do not supply state files, full plan JSON, or raw support cases.

Keep local data local

Preferences, case memory, vaults, logs, traces, databases, and generated output are excluded from the release. Ignore rules do not remove files already tracked in an existing repository.

Understand the boundary

Prompt instructions cannot sanitize data before a model receives it. This preview contains no automatic redaction service. Follow your employer’s AI and data handling requirements.

Never post private material in GitHub issues. Use synthetic reproductions. For a suspected exposure, follow SECURITY.md and an approved private reporting channel.

This page has no external assets, analytics, forms, or scripts. It stores no input. External project and documentation links connect only when you choose to follow them.

Installation makes no network requests and writes nothing to your home directory. It checks release hashes, refuses differing existing definitions and symlink destinations, and uses private permissions for generated files. Hashes detect changes; they do not authenticate a publisher.

Re-running the same version preserves preferences. When an existing configuration differs, inspect it manually rather than forcing an overwrite. No uninstall or automatic upgrade command is provided in this preview.

06 / Lessons built into this release

What the review taught us.

Export deliberately

A public release needs an explicit file allowlist. Copying a development folder can expose personal settings, archives, old case material, or private dependency links.

Separate source from state

Ship neutral definitions and blank preferences. Create personal configuration only on the tester’s machine. Keep generated files and case records outside published source.

Use Bob’s actual discovery paths

Project skills load from .bob/skills/; project modes use .bob/custom_modes.yaml. File creation alone does not prove the IDE loaded them.

Test failures, too

A good installation test checks dry-run, repeat installation, preserved preferences, conflicting settings, symlink escapes, tampering, and browser failure.

Match claims to evidence

Parsing a test fixture is not a successful agent response. An offline file-copy test is not a completed Bob conversation. Report automated and manual evidence separately.

Keep experimental scope visible

Excluded integrations stay excluded. A synthetic preview does not establish real-case privacy, production safety, autonomous accuracy, or verified support for every OS.

07 / Common questions

When something does not work.

I cannot see the mode or the skills.

Check that you opened the release root in Bob, ran the installer successfully, and reloaded the window. Inspect Settings → Skills and the mode picker. Record your Bob version if discovery still fails. Project definitions can take precedence over global skills with the same name.

The installer says an existing file differs.

It stopped before writing the planned definitions. Compare the named relative file with the release. Preserve your customizations and resolve the conflict manually; do not delete the whole workspace or use broad Git reset/clean commands.

The release integrity check fails.

A listed file is missing or changed. Obtain a clean reviewed release and compare its version and manifest. Do not bypass the integrity check to make installation continue.

The welcome page did not open.

Browser availability varies. If installation succeeded, open docs/welcome.html directly. A browser-launch failure does not undo installation. Use --no-open to suppress automatic opening intentionally.

The agent cannot retrieve documentation or run a command.

This preview mode has read and skill tools only. Supply an independently checked public excerpt or follow the suggested manual URL. Command execution, MCP, and customer-system access are outside this release.

Can I enter my name or use a real support case?

Personal signature fields are optional local preferences; do not commit them. This release is for synthetic testing. It has no automatic PII gateway or encrypted case storage, so keep real support cases out.
